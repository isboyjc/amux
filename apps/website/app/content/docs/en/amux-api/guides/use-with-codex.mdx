[Codex CLI](https://github.com/openai/codex) is OpenAI's AI coding agent for the terminal. Since Amux API Platform provides an OpenAI-compatible API, Codex CLI works seamlessly with it.

## Prerequisites

- Codex CLI installed ([installation guide](/docs/amux-api/guides/install-codex-cli))
- An Amux API Platform account with an API token ([Quick Start](/docs/amux-api/quick-start))

## Method 1: Environment Variables

Set the environment variables to point Codex CLI at Amux API Platform:

```bash
export OPENAI_BASE_URL="https://api.amux.ai/v1"
export OPENAI_API_KEY="your-amux-api-token"
```

For persistence, add them to your shell profile (`~/.bashrc`, `~/.zshrc`, etc.):

```bash
echo 'export OPENAI_BASE_URL="https://api.amux.ai/v1"' >> ~/.zshrc
echo 'export OPENAI_API_KEY="your-amux-api-token"' >> ~/.zshrc
source ~/.zshrc
```

## Method 2: CC-Switch

[CC-Switch](https://github.com/foreveryh/claude-code-switch) is a shell-based one-command model switcher supporting multiple providers and custom configurations.

## Method 3: CC-Switch-CLI

[CC-Switch-CLI](https://github.com/farion1231/cc-switch) is a cross-platform CLI tool (built in Rust) for managing Claude Code, Codex, and Gemini CLI provider configurations.

## Usage

Run Codex CLI as usual:

```bash
# Interactive mode
codex

# Single command
codex "explain this codebase"

# Full auto mode
codex --full-auto "fix the failing tests"
```

Codex CLI will automatically use Amux API Platform for all requests.

### Model Selection

By default, Codex CLI uses OpenAI's default model. You can specify a different model:

```bash
codex --model gpt-5.4 "review this code"
```

Available models through Amux API include GPT-5.4, GPT-4o, Grok series, MiniMax M2.5, and more. Check the [Quick Start](/docs/amux-api/quick-start) for the full list.

## Verify

```bash
codex "Hello, what model are you?"
```

If you receive a response, the connection is working correctly.

## Notes

- Amux API Platform is fully OpenAI-compatible, so no additional configuration is needed
- All Codex CLI features (streaming, safety modes, sandboxing) work as expected
- Available models depend on your Amux API account and credits

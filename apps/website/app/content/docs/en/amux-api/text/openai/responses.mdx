The OpenAI **Responses API** creates model responses with built-in support for multi-turn conversation, tool calls, and reasoning output. Compared to Chat Completions, Responses simplifies multi-turn / tool-state management via `previous_response_id`.

| Field | Value |
| --- | --- |
| **Method** | `POST` |
| **Path** | `/v1/responses` |
| **Full URL** | `https://api.amux.ai/v1/responses` |
| **Auth** | `Authorization: Bearer <API_TOKEN>` |
| **Request format** | `application/json` |
| **Response format** | JSON, or SSE when `stream=true` |

<Callout type="info">
Responses is OpenAI's newest unified endpoint, combining capabilities from Chat Completions and the Assistants API. If your project still uses Chat Completions, you can keep using [`/v1/chat/completions`](./chat-completions).
</Callout>

<Tabs items={['curl', 'Python', 'Node.js']}>
  <Tab value="curl">

```bash
curl https://api.amux.ai/v1/responses \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $AMUX_API_KEY" \
  -d '{
    "model": "gpt-5.4",
    "input": "Introduce Amux API in one sentence.",
    "instructions": "You are a concise assistant."
  }'
```

  </Tab>
  <Tab value="Python">

```python
import os
from openai import OpenAI

client = OpenAI(
    base_url="https://api.amux.ai/v1",
    api_key=os.environ["AMUX_API_KEY"],
)

response = client.responses.create(
    model="gpt-5.4",
    input="Introduce Amux API in one sentence.",
    instructions="You are a concise assistant.",
)

print(response.output_text)
```

<Callout type="info">
The official OpenAI SDKs (e.g. Python) expose a convenience property `response.output_text` that the SDK computes by concatenating `output_text` parts from `output[].content[]`. **This is SDK-side logic, not a JSON field returned by amux-api.** To get plain text without the SDK, walk `output[].content[]` and collect parts where `type === "output_text"`.
</Callout>

## Streaming

When `stream=true`, the response is an SSE event sequence with `event:` and `data:` lines:

```
event: response.created
data: {"type":"response.created","response":{"id":"resp_xxx","status":"in_progress",...}}

event: response.output_text.delta
data: {"type":"response.output_text.delta","delta":"Amux"}

event: response.output_text.delta
data: {"type":"response.output_text.delta","delta":" API"}

event: response.completed
data: {"type":"response.completed","response":{...}}
```

Common events:

| Event | Description |
| --- | --- |
| `response.created` | Response created (in_progress) |
| `response.output_item.added` | New output item begins (e.g. a new `message` / `function_call`) |
| `response.output_item.done` | Current output item completed |
| `response.output_text.delta` | Text increment |
| `response.output_text.done` | Current text block finished |
| `response.reasoning_summary_text.delta` | Reasoning summary increment |
| `response.reasoning_summary_text.done` | Reasoning summary finished |
| `response.function_call_arguments.delta` | Tool-call arguments increment |
| `response.function_call_arguments.done` | Tool-call arguments completed |
| `response.completed` | Response finished |
| `response.failed` | Response failed |
| `response.error` / `error` | Error event |

## Error Response

```json
{
  "error": {
    "message": "...",
    "type": "invalid_request_error",
    "param": "input",
    "code": "invalid_value"
  }
}
```

Error code semantics match [Chat Completions](./chat-completions#error-response).

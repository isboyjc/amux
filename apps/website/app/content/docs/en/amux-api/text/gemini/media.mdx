Gemini's multimodal understanding **reuses** the [`generateContent`](./chat) endpoint — simply add media parts to `contents[].parts[]`. This page focuses on multimodal usage: upload methods, supported MIME types, examples, and notes. For the full request / response field reference, see [Text Chat](./chat).

| Field | Value |
| --- | --- |
| **Method** | `POST` |
| **Path** | `/v1beta/models/{model}:generateContent` (same as text chat) |

<Callout type="info">
**Multimodal models**: We recommend `gemini-2.5-pro` / `gemini-2.5-flash` / `gemini-flash-latest` and similar models with vision and audio/video capability. Modality coverage varies by model — see [Models & Pricing](https://api.amux.ai/pricing).
</Callout>

## Media Upload Methods

Gemini supports two media input methods, both forwarded by amux-api:

<TypeTable
  type={{
    inlineData: {
      type: 'object',
      description: '**Base64 inline**: read the file as a Base64 string and include it directly. Shape: `{ "mimeType": "...", "data": "<base64>" }`. Snake_case aliases `inline_data` / `mime_type` are also accepted.',
    },
    fileData: {
      type: 'object',
      description: '**File API reference**: first upload via the Google File API to get a `fileUri`, then reference it in the request. Shape: `{ "mimeType": "...", "fileUri": "..." }`. Best for large files (>20MB) or repeated use.',
    },
  }}
/>

<Callout type="warn">
**Practical tips**:

- Keep the request body under **20MB** when possible. For larger payloads, prefer `fileData.fileUri`.
- For media on the public web, consider the `urlContext` tool, or download the file and use `inlineData`.
- amux-api does not manage Google File API storage. When using `fileData`, the file must already exist in the upstream account.
</Callout>

## Supported MIME Types

| Modality | Common MIME types |
| --- | --- |
| **Image** | `image/png`, `image/jpeg`, `image/webp`, `image/heic`, `image/heif` |
| **Document** | `application/pdf` |
| **Audio** | `audio/mpeg` (mp3), `audio/wav`, `audio/ogg`, `audio/flac`, `audio/aac` |
| **Video** | `video/mp4`, `video/mpeg`, `video/mov`, `video/avi`, `video/x-flv`, `video/webm`, `video/wmv`, `video/3gpp` |

The exact supported set depends on the model.

## Examples

### Image Understanding (Base64 Inline)

<Tabs items={['curl', 'Python', 'Node.js']}>
  <Tab value="curl">

```bash
IMAGE_BASE64=$(base64 < cat.png | tr -d '\n')

curl "https://api.amux.ai/v1beta/models/gemini-2.5-pro:generateContent" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $AMUX_API_KEY" \
  -d "{
    \"contents\": [{
      \"role\": \"user\",
      \"parts\": [
        { \"text\": \"What is in this image? Describe it in English.\" },
        { \"inlineData\": { \"mimeType\": \"image/png\", \"data\": \"$IMAGE_BASE64\" } }
      ]
    }]
  }"
```

  </Tab>
  <Tab value="Python">

```python
import base64
import os
from google import genai

client = genai.Client(
    api_key=os.environ["AMUX_API_KEY"],
    http_options={"base_url": "https://api.amux.ai"},
)

with open("cat.png", "rb") as f:
    image_b64 = base64.b64encode(f.read()).decode()

response = client.models.generate_content(
    model="gemini-2.5-pro",
    contents=[
        {"role": "user", "parts": [
            {"text": "What is in this image? Describe it in English."},
            {"inline_data": {"mime_type": "image/png", "data": image_b64}},
        ]},
    ],
)

print(response.text)
```

  </Tab>
  <Tab value="Node.js">

```ts
import { readFileSync } from 'node:fs';
import { GoogleGenAI } from '@google/genai';

const ai = new GoogleGenAI({
  apiKey: process.env.AMUX_API_KEY!,
  httpOptions: { baseUrl: 'https://api.amux.ai' },
});

const imageBase64 = readFileSync('cat.png').toString('base64');

const response = await ai.models.generateContent({
  model: 'gemini-2.5-pro',
  contents: [
    {
      role: 'user',
      parts: [
        { text: 'What is in this image? Describe it in English.' },
        { inlineData: { mimeType: 'image/png', data: imageBase64 } },
      ],
    },
  ],
});

console.log(response.text);
```

### Video Understanding (use fileData for large files)

```bash
curl "https://api.amux.ai/v1beta/models/gemini-2.5-pro:generateContent" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $AMUX_API_KEY" \
  -d '{
    "contents": [{
      "role": "user",
      "parts": [
        { "text": "Summarize the key scenes in this video with a timeline." },
        {
          "fileData": {
            "mimeType": "video/mp4",
            "fileUri": "https://generativelanguage.googleapis.com/v1beta/files/xxxxxxxx"
          }
        }
      ]
    }],
    "generationConfig": {
      "mediaResolution": "MEDIA_RESOLUTION_MEDIUM"
    }
  }'
```

## Controlling Media Resolution

Use `generationConfig.mediaResolution` to control how finely media is parsed (affects token cost and recognition quality):

<TypeTable
  type={{
    MEDIA_RESOLUTION_LOW: {
      type: 'string',
      description: 'Low resolution (most token-efficient).',
    },
    MEDIA_RESOLUTION_MEDIUM: {
      type: 'string',
      description: 'Medium resolution (default, recommended).',
    },
    MEDIA_RESOLUTION_HIGH: {
      type: 'string',
      description: 'High resolution (best detail, highest token cost).',
    },
  }}
/>

You can also set `mediaResolution` on a single `inlineData` part for per-input control, or use `videoMetadata` to specify video frame-sampling strategy.

## Usage Statistics

For multimodal requests, `usageMetadata.promptTokensDetails` breaks down input tokens by modality:

```json
{
  "usageMetadata": {
    "promptTokenCount": 1284,
    "candidatesTokenCount": 156,
    "totalTokenCount": 1440,
    "promptTokensDetails": [
      { "modality": "TEXT", "tokenCount": 24 },
      { "modality": "IMAGE", "tokenCount": 1260 }
    ]
  }
}
```

This makes per-modality billing breakdown easy.

## Notes

- **Request body size**: amux-api and the upstream both have body limits. Prefer `fileData.fileUri` when payloads exceed ~20MB.
- **Correct MIME types matter**: incorrect `mimeType` leads to upstream parsing failures.
- **Multimodal is token-heavy**: combine `mediaResolution` with [context caching](./chat#request-body) (`cachedContent`) to control cost.
- **Full reference**: for all request body fields (`generationConfig` / `tools` / `safetySettings` etc.), see [Text Chat](./chat).

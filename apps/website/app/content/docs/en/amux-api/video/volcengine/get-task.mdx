Query task status using the `id` returned by [Create Video Generation Task](./create-task).

## General

| Item | Value |
| --- | --- |
| **Method** | `GET` |
| **Path** | `/api/v3/contents/generations/tasks/{task_id}` |
| **Full URL** | `https://api.amux.ai/api/v3/contents/generations/tasks/{task_id}` |
| **Auth** | `Authorization: Bearer <AMUX_API_KEY>` |
| **Request body** | None |
| **Response format** | `application/json` |
| **Task isolation** | You can only query tasks you created |

<TypeTable

## Response Fields

<TypeTable
  type={{
    id: { type: 'string', description: <>Task ID</> },
    model: { type: 'string', description: <>Model name</> },
    status: { type: 'string', description: <><code>queued</code> / <code>running</code> / <code>succeeded</code> / <code>failed</code>; see <a href="#status-values">Status Values</a></> },
    content: { type: 'object', description: <>Present on success, <code>{`{ "video_url": "..." }`}</code></> },
    'content.video_url': { type: 'string', description: <>Video URL (amux proxy URL; download or re-host promptly)</> },
    resolution: { type: 'string', description: <>Resolution, e.g. <code>720p</code></> },
    duration: { type: 'integer', description: <>Duration (seconds)</> },
    ratio: { type: 'string', description: <>Aspect ratio, e.g. <code>16:9</code></> },
    'usage.completion_tokens': { type: 'integer', description: <>Generated tokens</> },
    'usage.total_tokens': { type: 'integer', description: <>Total tokens</> },
    error: { type: 'object', description: <>Present on failure, <code>{`{ "code": "...", "message": "..." }`}</code></> },
    created_at: { type: 'integer', description: <>Creation time (Unix seconds)</> },
    updated_at: { type: 'integer', description: <>Update time (Unix seconds)</> },
  }}
/>

> Not-ready / not-applicable fields are omitted (no `content` / `usage` while generating; no `error` on success).

## Status Values

| status | Meaning |
| --- | --- |
| `queued` | Queued (submitted / not yet started) |
| `running` | Generating |
| `succeeded` | Done, `content.video_url` available |
| `failed` | Failed, see `error` |

## Polling Tips

After creation, poll the query endpoint with the returned `id` until `status` is `succeeded` or `failed` — every 3–5 seconds is recommended.

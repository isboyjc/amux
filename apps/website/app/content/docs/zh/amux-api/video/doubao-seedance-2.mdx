豆包 Seedance 2.0 是字节跳动火山方舟（Volcengine Ark）推出的多模态视频生成模型，支持文本、图像、视频、音频四种输入模态混合，最多 9 张图 / 3 个视频片段 / 3 个音频片段。amux-api 同时提供 **火山原生端点** 与 **amux 通用端点** 两种调用方式。

<Callout type="info">
**火山 v3 协议兼容**：火山原生端点现已完整兼容火山方舟 v3 协议的**创建任务**与**查询任务状态**两个接口，请求路径 / 请求体与火山官方对齐。完整字段格式见独立文档：[创建视频生成任务（火山 v3 格式）](./volcano-create-task)、[查询任务状态（火山 v3 格式）](./volcano-get-task)。本页聚焦 Doubao Seedance 2.0 的模型专属用法。
</Callout>

## 模型版本

| 模型 ID | 定位 | 适用场景 |
| --- | --- | --- |
| `doubao-seedance-2.0` | 标准版 | 画质优先、最终成片，支持 720p / 1080p |
| `doubao-seedance-2.0-fast` | 加速版 | 速度优先、价格更低，适合 prompt 迭代 / 草样。**仅支持 720p**，不支持 1080p |

具体单价见 [https://api.amux.ai/pricing](https://api.amux.ai/pricing)。

## 创建视频生成任务

提供两种调用方式，二者共用同一套 [获取任务状态](./get-task) 接口：

- **方式一（火山原生）**：`POST /api/v3/contents/generations/tasks` — 与火山官方契约一致，火山原生 SDK 改 `base_url` 即可使用
- **方式二（amux 通用）**：`POST /v1/video/generations` — 跨厂商统一格式，火山专属字段通过 `metadata` 透传

### 方式一：火山原生端点

| 项目 | 值 |
| --- | --- |
| **请求方法** | `POST` |
| **完整 URL** | `https://api.amux.ai/api/v3/contents/generations/tasks` |
| **认证** | `Authorization: Bearer <AMUX_API_KEY>` |
| **请求格式** | `application/json` |
| **响应格式** | `application/json` |

amux 网关识别"火山原生格式"的条件：请求体含 `content` 字段 **且** 不含 `prompt` 字段。同时存在两者会被当作通用格式处理（走方式二的转换链路）。

#### 场景与角色

提交任务可分为以下 4 种场景，**含图像的 3 种场景互斥，不能在同一任务中混用**：

| 场景 | image_url | video_url | audio_url |
| --- | --- | --- | --- |
| 文生视频 | — | — | — |
| 图生视频（首帧） | 1 张，`role: first_frame` | — | — |
| 图生视频（首+尾帧） | 2 张，`role: first_frame` + `last_frame` | — | — |
| 多模态参考生视频 | 1–9 张，`role: reference_image` | 0–3 段 | 0–3 段 |

> 多模态参考模式下，三种模态都是可选的（可只传图、只传视频、只传音频，或任意组合）。

**首尾帧场景的特殊行为**：

- 首尾帧图片可相同
- 首尾帧宽高比不一致时，**以首帧为主**，末帧自动裁剪适配

**首尾帧 × 多模态参考的近似实现**：

多模态参考模式下，可在 prompt 中用 `@imageN` 指定某张参考图作为首帧 / 末帧，间接实现"首尾帧 + 多模态参考"效果。但若需**严格保障首尾帧锁定**，请用图生视频-首尾帧场景（明确 `role: first_frame` / `last_frame`）。

#### 资源约束

| 资源 | 单文件上限 | 时长 | 数量 | 格式 |
| --- | --- | --- | --- | --- |
| 图像（image_url） | 30 MB | — | 见上方场景表 | HTTP/HTTPS URL 或 Base64 data URL |
| 视频（video_url） | 50 MB | 单段 [2, 15] 秒 | ≤ 3 段，总时长 ≤ 15 秒 | mp4 / mov；分辨率 480p / 720p / 1080p |
| 音频（audio_url） | 15 MB | 单段 [2, 15] 秒 | ≤ 3 段，总时长 ≤ 15 秒 | wav / mp3 |

<Callout type="warn">
**整体限制**：请求体总大小 ≤ 64 MB。**大文件请勿使用 Base64 编码**，推荐使用公网 HTTP/HTTPS URL 提交，既避开 64 MB 限制，又减少传输延迟。
</Callout>

### 方式二：amux 通用端点

跨厂商统一契约。常规字段（`prompt` / `image` / `images`）写顶层，火山专属字段通过 `metadata` 透传。

| 项目 | 值 |
| --- | --- |
| **请求方法** | `POST` |
| **完整 URL** | `https://api.amux.ai/v1/video/generations` |
| **认证** | `Authorization: Bearer <AMUX_API_KEY>` |
| **请求格式** | `application/json` |

通用字段定义见 [创建视频生成任务（通用）](./create-task#请求体参数)。

<Callout type="warn">
**`prompt` 强制必填**：amux 校验层强制要求 `prompt` 非空，即便首/末帧锁定或纯参考图模式也必须提供 prompt。
</Callout>

#### 顶层字段

</Callout>

#### 指定图像角色 / 注入视频 / 音频

通用端点要让图像带 `role`、或注入 `video_url` / `audio_url`，统一通过 `metadata.content` 提供完整的 Doubao content 数组（结构同方式一的 [ContentItem 元素](#contentitem-元素)）：

```json
{
  "model": "doubao-seedance-2.0",
  "prompt": "镜头缓慢推近",
  "metadata": {
    "ratio": "16:9",
    "duration": 5,
    "content": [
      { "type": "image_url", "image_url": { "url": "https://example.com/start.jpg" }, "role": "first_frame" },
      { "type": "image_url", "image_url": { "url": "https://example.com/end.jpg"   }, "role": "last_frame"  }
    ]
  }
}
```

顶层 `image` / `images` 中的图会被加入 content 但 **不带 role** — 上游会按默认行为处理。如需精确控制角色 / 多模态，统一走 `metadata.content`。

<Callout type="warn">
**3 种场景互斥**：图生视频-首帧、图生视频-首尾帧、多模态参考生视频不能在同一任务中混用，详见上方 [场景与角色](#场景与角色)。

amux adapter 还有一个特殊处理：**当 content 仅含 `reference_image`（无首/末帧）时，duration 字段会被自动剔除** — 因为上游对多模态参考模式不接受 duration，会直接报 InvalidParameter。
</Callout>

```bash
        { "type": "audio_url", "audio_url": { "url": "https://example.com/voice.mp3" } }
      ]
```
```bash
    }
  }'
```

## 获取视频生成任务状态

无论使用方式一还是方式二提交，都可通过以下接口查询任务状态与下载视频，传入创建时返回的 `id` 即可：

| 用途 | 端点 |
| --- | --- |
| 查询任务状态（通用格式） | [`GET /v1/video/generations/{task_id}`](./get-task) |
| 查询任务状态（火山 v3 格式） | [`GET /api/v3/contents/generations/tasks/{task_id}`](./volcano-get-task) |
| 直接下载视频字节流 | `GET /v1/videos/{task_id}/content` |

通用格式返回归一化后的统一结构，详见 [获取视频生成任务状态](./get-task)；火山 v3 格式返回火山官方 v3 任务结构，详见 [查询任务状态（火山 v3 格式）](./volcano-get-task)。

## 计费说明

amux-api 对 Doubao Seedance 2.0 系列做了**视频输入折扣识别**：当请求 content 中检测到 `video_url` 类型条目（视频续生 / 多模态视频参考）时，单价会自动按上游"含视频输入档"折算，约为基准价的 0.59 ~ 0.61。无视频输入按基准单价计费。

> 注意：虽然"含视频输入档"单价更低，但输入视频本身会额外占用输入 Token，叠加后**最终总价与不带视频输入相差不多**——折扣只是定价分档，不是净优惠。

此外，**`resolution: "1080p"` 单价高于 `720p`**，且 `doubao-seedance-2.0-fast` 不支持 1080p — 详见 [pricing](https://api.amux.ai/pricing)。

## 常见问题

<Accordions>
  <Accordion title="标准版 vs Fast 版怎么选？">
    - **画质优先**：选 `doubao-seedance-2.0`，画面质量与一致性更好，且支持 1080p 输出
    - **速度优先**：选 `doubao-seedance-2.0-fast`，生成更快、单价更低，适合批量探索 / 草样。**仅支持 720p**

    实践经验：先用 Fast 版快速迭代 prompt，确定方向后切到标准版生成最终成片（如需 1080p 必须切到标准版）。
  </Accordion>

  <Accordion title="为什么 `metadata.first_frame` 没生效？">
    Doubao adapter 不识别 `first_frame` / `last_frame` / `reference_images` 这些**单独的 metadata 键**，它们只在 `metadata.content` 数组的 `role` 字段里有效。

    正确写法：
    ```json
    "metadata": {
      "content": [
        { "type": "image_url", "image_url": { "url": "..." }, "role": "first_frame" }
      ]
    }
    ```
  </Accordion>

  <Accordion title="顶层 duration 不生效？">
    Doubao adapter 在通用端点只读 `req.Seconds`（顶层 `seconds` 字符串字段）和 `metadata.duration`，**不读 `req.Duration`**。要在顶层指定时长，写 `"seconds": "5"`（字符串），或者直接用 `metadata.duration: 5`（推荐）。
  </Accordion>

  <Accordion title="prompt 必须有吗？">
    通用端点（方式二）必须有，amux 网关在校验层强制要求 prompt 非空，即使是首/末帧锁定或纯参考图模式也要给一段 prompt（实测火山上游 / 阿里 / Sora 等即便有 reference image 也会因缺 prompt 直接拒）。火山原生（方式一）则通过 content 数组中的 `text` 元素提供。
  </Accordion>

  <Accordion title="多模态输入有什么上限？">
    单次请求上限：≤ 9 张图、≤ 3 段视频、≤ 3 段音频；单文件 ≤ 30 MB（图）/ ≤ 50 MB（视频）/ ≤ 15 MB（音频）；请求体总大小 ≤ 64 MB。完整规则见上方 [资源约束](#资源约束)。
  </Accordion>

  <Accordion title="生成的视频没有声音？">
    检查 `generate_audio`（默认 `true`）。如果显式传了 `false`，产物为纯画面。注意部分早期模型变体可能不支持音频生成，以单价表标注的能力为准。
  </Accordion>

  <Accordion title="传了 trace_id 为什么没回传？">
    网关当前**不支持** `trace_id`、`rpf_auto_detect` 这两个上游参数 — 客户端即使传入也会被网关丢弃，不会转发到上游，因此回调中不会带 `trace_id`。要关联回调与原始请求，请改用自己的 `callback_url` 路径或查询参数来携带业务标识。
  </Accordion>

  <Accordion title="callback_url 没收到回调？">
    上游会从公网直连你提供的 `callback_url`，请确保：

    - URL 公网可达，建议使用 HTTPS
    - 服务端能在数秒内返回 2xx 状态码
    - 不要把 callback 作为唯一获取结果的方式 — 建议 callback + 轮询双保险
  </Accordion>
</Accordions>
